# Native underlay evidence and local density requests

`FormorixUnderlay` separates three questions: where the actual core/skin interface lies, whether a completely filled existing Orca layer could reach it, and whether the actual native extrusion paths reach the finite interface samples. It does not generate supports, establish mechanical strength or adhesion, change Flow, schedule operations, or release experimental printing.

## Interface preparation

`prepare(FormorixHybrid::Result&, Options, cancel)` replaces the earlier path-derived interface samples with samples from `FormorixGeometry::Partition.interfaces` whose two owners are the conventional core (region 0) and the relevant skin region. Interfaces between two skin materials are not misidentified as core support. The source interface orientation is outward from its first owner; preparation reverses it when necessary to obtain the normal pointing from core toward skin. Contact rays point in the opposite direction.

Each original triangle is subdivided along its longest edge until the finite sample triangle meets `max_sample_edge` (default 0.5 mm). Its centroid is the contact sample. Each `Probe` retains the original interface and face indices, centroid barycentric coordinates in that face, the three finite footprint vertices, normal, and leaf area in mm². Area-weighted statistics therefore do not give a finely triangulated patch disproportionate weight. The sum of the leaf areas represents the sampled interface area; it is not a proof that material contacts every point of those triangles.

Preparation stages its results and replaces the hybrid sample arrays only after success. Invalid data, cancellation or resource exhaustion clears stale samples and dependencies. A region without a core interface has no artificial samples: it is explicitly marked as requiring external support. Zero samples never establish support coverage.

## Native layer versus extrusion-path gaps

After preparation the caller runs `FormorixHybrid::audit_underlay` on the actual `UnderlaySegment` list. That audit retains strict and raw geometric contact distances separately. Nonunit supply lacks a calibrated cross-section and remains strict `UnknownGeometry`, even when its unmodified native cross-section has raw contact. Unsupported sections such as bridges remain independently marked by `raw_geometry_unknown`.

`analyze` consumes those matching contacts and the actual `FormorixCorePreview::LayerSlice` records. Layer polygons are in scaled source-model XY, including their holes. `print_bottom_z` and `print_top_z` determine the finite deposited-layer prism. They may differ from the geometric `bottom_z`/`top_z`, for example because of raft lift. `local_origin` must not be applied again.

For a raw missing contact, the module intersects the inward ray with the Z interval and polygon boundaries of nearby native layers, including holes, within the finite search distance (default 0.5 mm). The closest candidate is compared with the same nominal contact allowance as the native path audit: `min(0.05 mm, surface layer height / 4)`. If even a fully filled native layer cannot approach within that allowance, the raw classification is `NativeLayerGap`. Increasing infill density cannot fix that native layer/staircase mismatch. If a filled layer could approach but the actual path does not, the raw classification is `PathGap`. Missing layer data, unsupported native geometry, missing core evidence and numerically borderline distances remain unknown. A separate band of eight coordinate-grid units plus coordinate-dependent floating arithmetic allowance avoids deciding directly on the threshold.

The prism calculations and area-weighted observations are finite numerical diagnostics, not certified whole-footprint or global nearest-distance bounds. `coverage_bounded` remains false. `RegionEvidence` area values describe the raw classifications. The stricter contact kinds are preserved for uncalibrated Flow; raw native-layer gap counts and markers remain available alongside those strict unknowns.

## Local dense-transition requests

Requests are generated only when `dense_underlay` is explicitly enabled and the requested density is positive. A sample must be a raw path gap with known native section geometry, and its fully filled native layer must geometrically reach the contact allowance. Missing-core contacts do not create requests. When `use_infill=false`, existing ordinary infill remains excluded as contact. Explicitly enabling `dense_underlay` nevertheless allows that excluded sample to request new local dense-transition work. Only actual regenerated paths carrying `dense_transition=true` become eligible, and only while that region's dense-underlay option remains enabled. Creating a request never authorizes the previous ordinary infill paths. Nonunit Flow can still produce a geometric request from its raw gap, but the request and its eventual regenerated paths do not convert strict unknown geometry into certified contact.

The finite local request footprint is the projected leaf-triangle bounding rectangle, expanded by half the configured surface line width. This deliberately conservative request area also remains finite for vertical interfaces; it is not presented as the exact deposited bead footprint. It is translated to the candidate inward contact and intersected with that actual layer's polygon. Requests for the same region and layer are united. Native holes and the layer contour remain excluded. The requested density is copied unchanged, never silently raised to 100 percent. The Z interval and slice height supplied to the native modifier are the original geometric layer coordinates, not raft-lifted print coordinates.

`CorePreview` independently validates each request and decides whether its density actually exceeds the unchanged native baseline. After a real modifier rerun, the caller must repeat the path audit and analysis using the regenerated paths. No contact is inferred merely because a request exists. A single local density pass does not promise that all gaps will disappear.

## Dependencies and failure contract

Analysis records Core → Surface, or Core → DenseTransition → Surface when local density work is requested. These are requirements, not a completed schedule. A region without a core interface receives an explicitly unassigned external-support prerequisite before its Surface operation. Its head is -1, its material is empty and `assigned=false`; the existing dependency model refuses to consider that prerequisite complete even if its ID accidentally appears in a completed set. No synthetic support toolpath or tool assignment is created.

Independent limits cover input faces, samples, subdivision work, native layer candidates, polygon vertices, polygon-edge work and requests. Native output ceilings are 256 requests, 2048 vertices per request and 65536 request vertices in total; callers may lower these limits but cannot exceed the native modifier API. The separate input-layer polygon budget remains one million vertices by default. Exceeding an output limit discards all staged requests before a native reslice is attempted. Cancellation is checked during subdivision, between layer queries and periodically during polygon-edge work. Clipper union/intersection is checked before and after the library call; its internal allocation and execution are not immediately interruptible. These are cooperative resource controls, not a hard wall-clock or memory bound.

Failures return no actionable requests or manufacturing dependencies. `Status::Complete` means this finite analysis completed; it is not support certification. Tests cover source-face/area retention, both interface orientations, native staircase gaps, layer holes, raft/source coordinates, vertical interfaces, local density opt-in, nonunit Flow, full-wall external dependencies, stale metadata and exhausted budgets. Separate native integration tests exercise actual Orca paths and reslicing; finite synthetic prism tests do not replace that evidence.
